### V1

*Rationale: Founder voice opens with the autonomous-company idea, then shows each part of the machine in order.*

(1/8) I built Suede Agent Studio for the company I wanted to run: one founder, a visual flow graph as staff, and scheduled agents that keep working while I sleep. Here is the machinery behind it.

(2/8) I start on a node-graph canvas. I wire specialized agents into a flow: input, reasoning, branches, Suede tools, and output. Each node has one job, so I can read the whole operation from left to right.

(3/8) Then I add a Schedule node. The schedule fires at the cadence I set, and the flow runs without me at the keyboard. That turns a diagram into staff that clocks in for repeat work.

(4/8) I set a price per call before launch. The execution engine keeps a per-node USDC cost ledger, so I can see what a run costs and what the endpoint charges.

(5/8) When I launch, Suede hosts the flow and makes it callable. I do not manage API keys or servers. Payment stays separate until the Live deployment, settlement gates, and payout are ready.

(6/8) That endpoint is not limited to my own workflow. Other agents and developers can call an available preview; once payment is enabled, they pay for the call through x402 v2.

(7/8) Suede publishes launched agents through a .well-known x402 discovery index. Another agent can find the endpoint, read what it offers, and buy the call machine to machine.

(8/8) On a payment-enabled service, the caller pays exact USDC on Base and the payment routes to the configured wallet. The canvas runs the work. The schedule keeps it running. x402 handles the transaction. That is the operating machinery of an autonomous company.

## LinkedIn post

### V1

*Rationale: A capability comparison starts with readable automation, then adds commerce, metering, and ownership rails.*

Most workflow tools stop when the automation finishes.

Suede Agent Studio gives your team a visual node graph they can inspect: inputs, decisions, schedules, branches, and outputs. The difference starts at launch.

A launched flow becomes callable and advertises its current state. You set the per-call price. Once payment readiness is complete, other agents can discover the payment-enabled endpoint through the .well-known x402 index, call it, and settle exact USDC on Base.

That is the commerce layer Gumloop-class tools do not have. They move data through workflows. Agent Studio also lets workflows transact.

The same published service can expose its A2A interface and, when payment readiness is complete, exact x402 v2 settlement in USDC on Base. Identity, IP registration, and royalty actions are separate workflow capabilities rather than payment rails.

Your team can read the workflow on the canvas, monitor live progress in the run dock, and see what each run costs and charges.

Automation becomes an operating system for work, money, and rights.
